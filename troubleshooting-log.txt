- Issue: Private instances could not reach the internet for yum updates.
- Solution: Created a Private Route Table and added a route for 0.0.0.0/0 pointing to the NAT Gateway ID.
- Note: Ensured NAT Gateway was created in the Public Subnet and assigned an Elastic IP.
# Troubleshooting Log: Module 4 (Web Tier & ALB)

### Issue 1: Target Group Status - "Unused" / 503 Service Unavailable
- **Observed Behavior:** ALB DNS URL returned a 503 error; Target Group showed instance as "Unused".
- **Root Cause:** Availability Zone Mismatch. The EC2 instance was in 'ap-south-1c', but the ALB was not configured to route traffic to that specific zone.
- **Resolution:** Modified ALB 'Network Mapping' to include the subnet corresponding to 'ap-south-1c'.

### Issue 2: Connection Timed Out (Browser Access)
- **Observed Behavior:** Browser failed to connect to the ALB DNS name.
- **Root Cause:** Security Group Inbound rules on the Web Server were not permitting traffic from the Load Balancer.
- **Resolution:** Added an Inbound Rule to 'SRJ-Web-SG' allowing HTTP (Port 80) traffic with the Source set to 'SRJ-ALB-SG'.

### Issue 3: SSH Session Termination
- **Observed Behavior:** Error `client_loop: send disconnect: Connection reset`.
- **Root Cause:** SSH session timed out due to inactivity.
- **Resolution:** Re-initiated the SSH connection from the local terminal using the Agent Forwarding command (`ssh -A`).
[Phase 5 - S3 Storage]
- Issue: Private instance could not access S3 buckets.
- Solution: Attached an IAM Role to the EC2 instance instead of using hardcoded access keys for security.
- Issue: AWS CLI on Windows was not returning results.
- Solution: Re-configured 'aws configure' with the correct region (ap-south-1) and valid IAM User credentials.
[Phase 6 - EFS Storage]
- Issue: Mount command was hanging/timing out on the EC2 instance.
- Solution: Verified that the EFS Security Group allows Port 2049 from the Web Server's Security Group.
- Issue: Windows unable to recognize the 'mount' command for network drives.
- Solution: Enabled the 'Services for NFS' feature in Windows Features settings to support the NFS protocol.
[Phase 7 - RDS Database]
- Issue: Initial connection attempt returned 'Access Denied (1045)'.
- Solution: Double-checked the master credentials and re-entered the correct password during the CLI login process.
- Issue: Database not visible to the Web Server.
- Solution: Ensured that 'Full Configuration' was used during creation to place the RDS instance in the correct custom VPC and private subnets.
- Issue: Observed unexpected text in terminal buffer during SQL execution.
- Root Cause: Clipboard buffer artifacts from the SSH terminal session.
- Resolution: Cleared the session and re-authenticated. Confirmed database integrity using 'SHOW TABLES'.
- Issue: ERROR 1046 (No database selected).
- Resolution: Always run the 'USE [database_name];' command after initiating a new MySQL session.
[Phase 8 - Auto Scaling & Networking]
- Issue: Newly launched ASG instances were not visible in the ALB Target Group.
- Solution: Updated ASG settings to correctly associate with the existing Target Group during creation.
- Issue: Private instances could not perform 'yum update' or reach external sites.
- Root Cause: Missing route to the internet in the Private Route Table.
- Fix: Added a 0.0.0.0/0 route pointing to the NAT Gateway in the Private Route Table. Verified with 'ping google.com'.
- Observation: Observed 'Clipboard Buffer' artifacts in terminal during SQL execution; resolved by clearing the session.
- Issue: CloudWatch graph not showing data for individual instances.
- Solution: Switched from 'Per-Instance Metrics' to 'By Auto Scaling Group' metrics for automated tracking of dynamic instances.
- Observation: SNS subscription remained in 'Pending' state until manually confirmed via the verification email.
- Logic: Understood that 'Desired Capacity' in ASG and CPU Alarms work together to maintain system stability.
